# 공장 운반 작업

## 실행

1. 이 폴더의 start.ps1을 PowerShell로 실행하거나 Python 3.10 이상에서 server.py를 실행합니다.
   python server.py
2. 브라우저에서 http://127.0.0.1:8765 를 엽니다.
3. Unreal의 Factory 맵을 플레이합니다.
4. 작업 화면에서 팔레트 번호와 빈 선반을 선택하고 운반을 등록합니다.
5. 해당 팔레트를 수동으로 집어 포크 높이 15~60cm로 맞추고 수동 조작을 멈춥니다.
6. 서버가 작업을 배정하고 지게차가 선반 이동·하역·포크 회수를 수행합니다.

등록된 팔레트가 실제로 포크에 지지된 경우에만 배정됩니다. 자동 집기는 별도 기능과 연결할 수 있습니다.
기존 Unreal의 구역·번호 버튼도 계속 사용할 수 있습니다.

## 공장

- A~F 각각 12칸 × 3층, 총 216자리
- 아래층 01~12, 가운데층 13~24, 위층 25~36
- 선반 앞 교차 통로 바깥에 INBOUND / WAIT / OUTBOUND 표지와 바닥선 생성
- 선반 점유는 시뮬레이션의 실제 팔레트 좌표로 확인
- 팔레트 ID가 비어 있으면 플레이 중 P-001 형식으로 자동 부여
- 지속적으로 고정할 팔레트 번호는 에디터의 PalletId 속성에 지정

## 작업과 저장

상태는 queued → assigned → moving → unloading → withdrawing → completed로 진행합니다.
같은 팔레트나 선반에 작업을 중복 등록할 수 없습니다.
완료 보고 시 팔레트가 목적지에 있고 포크 적재가 해제됐는지 서버가 다시 검사합니다.
중단·취소 시 팔레트는 현장 위치에 남으며 자동으로 재시도하지 않습니다.
연결이 끊기면 배정 작업을 중단하고 상태를 기록합니다.
서버 또는 시뮬레이션을 재시작한 진행 작업은 interrupted로 처리해 재배정을 막습니다.

작업 이력은 Saved/transport.sqlite에 저장됩니다.
선반·팔레트 좌표는 Factory 플레이에서 받은 최신 상태를 사용하며 5초 넘게 끊기면 새 작업을 받지 않습니다.
입출고 구역 표시는 시뮬레이션 배치이며 실제 설비 사양 또는 실측 데이터는 아닙니다.

## API

- GET /api/state — 연결·팔레트·선반·작업
- POST /api/jobs — {"pallet":"P-001","destination":"D-20"}
- POST /api/jobs/{id}/cancel — 작업 취소 요청
- POST /api/sync — Unreal 전용 상태 보고·배정 응답

기본 서버는 로컬 컴퓨터의 127.0.0.1에만 연결됩니다.
운영 설비에 연결하려면 인증·권한·장비별 통신 규약과 장애 대응 검증이 별도로 필요합니다.
