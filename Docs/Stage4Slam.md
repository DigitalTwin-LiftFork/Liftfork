# Stage 4 — incremental LiDAR SLAM

## Implemented

`UForkliftSlamComponent` is attached to each `AAutomatedForklift` and consumes the existing `FForkliftLidarScan` snapshots. It implements an incremental planar SLAM pipeline:

1. Convert valid, near-horizontal LiDAR returns from `lidar_link` into the forklift body frame using the recorded sensor extrinsic transform.
2. Define the first scan's body pose as `(0, 0, 0)` in an arbitrary `map` frame; no world pose is assumed.
3. For later scans, search candidate X/Y/yaw poses around the prior estimate. Score candidate scans against previously occupied and free cells in the accumulated map (correlative scan-to-map matching).
4. Accept the pose only when enough returns overlap occupied map cells and the matched fraction meets its threshold. Otherwise keep the previous pose, set tracking invalid, and skip map integration for that scan.
5. Transform accepted scan rays with the estimated pose and update a global 2D occupancy grid using bounded log odds: hit endpoints add occupied evidence, traversed cells add free evidence, and repeated contradictory observations can change a cell's state.
6. Expose the estimated map pose, tracking validity, match fraction, sequence/timestamp, and map-cell queries through the component. Optional debug drawing renders the estimated pose and occupied map points.

The estimator and map integration do not read `GetActorTransform`, component world position, actor labels, or ground-truth coordinates. `MapToWorldForDebug` is strictly a rendering alignment setting; changing it does not affect estimates or map contents. The current IMU output is not used by this SLAM implementation because it is currently generated by differencing the simulated component's world transform and is explicitly marked as ideal/ground-truth-derived.

## Scope and limitations

This is real scan-to-map localization plus incremental occupancy mapping, not a prerecorded map or truth-pose mapper. It is an initial 2D SLAM implementation, not a production navigation stack. It does not have a loop-closure detector or pose graph, so long trajectories can drift. Dynamic people, moving pallets, repeated identical shelf rows, sparse geometry, poor LiDAR visibility, or motion beyond the configured local search window can make matching fail. When that happens it reports `bTrackingValid=false` and stops adding scans until a scan matches again; it does not silently integrate at the wrong pose.

The map is per forklift and initially 20 m square at 10 cm resolution. Increase **SLAM | Map > Map Size Cm** for a larger warehouse; memory grows approximately with the square of map size divided by resolution squared. This stage does not send commands to the drive, perform route planning, avoid obstacles, detect pallet identity, or implement loop closure.

## Useful editor properties

- **SLAM | Status > Estimated Pose**: current arbitrary map-frame X/Y/yaw, scan sequence, matched fraction, initialization and tracking flags.
- **SLAM | Scan matching**: local translation/yaw search window, step size and acceptance thresholds. Default search supports the existing 10 Hz LiDAR, ordinary steering changes, and up to roughly 20 cm travel per scan; increase the window if scan rate or speed changes.
- **SLAM | Filtering**: near-horizontal ray and floor-return filters for the current sensor mount and chassis dimensions.
- **SLAM | Debug > Draw Map / Draw Estimated Pose**: shows occupied cells and estimated axes. By default the map frame is drawn at world origin; set **Map To World For Debug** to align the display to a chosen location. This transform is visualization-only.

## How to test in UE 5.8.3

1. Restart the editor after compiling so the new reflected component is loaded, then open `Map1` and start PIE.
2. Select the forklift during PIE and inspect **IncrementalLidarSlam**. Wait for at least two scan sequence increments. The first scan initializes a map at `(0,0,0)` and is not yet a matched pose; subsequent scans in a static, geometrically distinct area should set **Tracking Valid** and produce a nonzero matched fraction.
3. Enable **Draw Estimated Pose** and **Draw Map**. Drive slowly past a wall corner or an asymmetric set of shelves, stop, then rotate and translate in small increments. The green estimated axis should move/turn smoothly and red points should persist in the map frame rather than being replaced by a body-centric snapshot.
4. Compare against the `FORKLIFT_SLAM` Output Log line: scan sequence advances, match state is true in a well-observed static area, and estimated pose changes with movement.
5. Temporarily turn the forklift toward open space or move it faster than the local search range. The expected safe behavior is a tracking-invalid state and no map integration for that scan, rather than a jump to the actor's actual position.
6. Restart PIE. The component begins a new map at its arbitrary origin; persistence across runs is not implemented.

Keep the previous Stage 0–3 pallet contact and collision regression checks in `Stages1-3.md`; this stage does not change those systems.
